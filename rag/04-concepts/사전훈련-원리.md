## 레벨 0 — 이 프로젝트가 하려는 일 (한 문장)

> **"다음에 올 글자 하나를 맞히는 연습"만 수천 번 시키면, 컴퓨터가 글을 쓰기 시작한다.**

말도 안 되는 소리 같지만 사실입니다. 그리고 이게 ChatGPT가 만들어진 원리 그 자체예요. 여러분은 이걸 **아주 작게** 직접 만들어서 눈으로 확인할 겁니다.

전체 흐름 — 코드 파일 순서가 곧 이 순서입니다:

```
글자 → ① 번호로 바꾸기 → ② 문제집 만들기 → ③ 모델이 찍기 → ④ 채점하기
       (tokenizer)      (x, y 데이터셋)     (logits)      (loss)
                                                ↑            │
                                          ⑥ 글 쓰기      ⑤ 조금 고치기
                                          (sampling)     (optimizer) → ③으로 반복
```

## 레벨 1 — Tokenization: 컴퓨터는 글자를 모른다

컴퓨터(신경망)는 **숫자만** 계산할 수 있습니다. 'h'가 뭔지 몰라요. 그래서 **글자 ↔ 번호 암호표**가 필요합니다. 그게 tokenizer.

```
"hello" → [7, 4, 11, 11, 14]      ← encode (글자를 번호로)
[7, 4, 11, 11, 14] → "hello"      ← decode (번호를 글자로, 반드시 원래대로!)

vocab = 이 텍스트에 나오는 모든 글자의 목록. 셰익스피어 영어 텍스트면 65개.
```

- 진짜 LLM은 글자 하나가 아니라 **자주 붙어 다니는 글자 뭉치**(BPE, 예: "ing", "지원")를 한 단위로 씁니다. 하지만 **원리는 똑같습니다**: 텍스트 ↔ 번호의 양방향 변환.
- 한국어를 글자 단위로 하면 vocab이 수천 개(음절 종류가 많아서)로 커집니다 — 그래서 tiny 실험은 **영어 텍스트 추천**. (한국어로 해보고 뭐가 달라지는지 관찰하는 건 좋은 토요일 탐구!)

## 레벨 2 — Next-token prediction: 정답지를 만들 필요가 없다

머신러닝의 가장 큰 골칫거리는 "정답 라벨을 사람이 일일이 달아야 한다"는 것입니다. 고양이 사진 10만 장에 "고양이"라고 태그를 달려면… 사람이 죽어납니다.

**그런데 글에는 마법 같은 성질이 있습니다. 텍스트 자신이 정답지입니다.**

```
텍스트: "hello",  block_size=3 (한 번에 3글자씩 본다)

x = [h, e, l]     ← 문제
y = [e, l, l]     ← 정답 (x를 한 칸 오른쪽으로 민 것뿐!)
```

**한 칸 밀기**가 전부입니다. 그리고 이 한 쌍 안에 **문제가 3개** 들어 있어요:

```
  "h"       다음은? → e     ✅ 정답은 y의 첫째 칸
  "h,e"     다음은? → l     ✅ 정답은 y의 둘째 칸
  "h,e,l"   다음은? → l     ✅ 정답은 y의 셋째 칸
```

### 왜 하필 "다음 글자 맞히기"인가? (4주차 관문 질문)

1. **정답이 공짜다** — 인터넷의 모든 글이 그대로 문제집이 됩니다. 사람이 라벨을 안 달아도 돼요. (이걸 자기지도학습이라 부릅니다)
2. **다음 말을 잘 맞히려면 언어의 거의 전부가 필요하다** — 이게 진짜 핵심입니다:
   - "밥을 먹었___" → "다" (문법을 알아야 함)
   - "대한민국의 수도는 ___" → "서울" (사실을 알아야 함)
   - "철수는 배가 고팠다. 그래서 그는 ___" (앞 문맥을 기억해야 함)

   > **단순한 목표 하나가 종합 능력을 강제로 길러냅니다.** 이게 LLM이 똑똑해진 비밀이에요.
3. **공부하는 법과 글 쓰는 법이 같다** — 잘 맞히는 모델 = 한 글자씩 이어 붙이면 글이 되는 모델.

- **train/val 나누기**: 90%로 공부하고, 10%는 숨겨뒀다가 모의고사로 씁니다. 공부한 문제만 잘 푸는 건 이해가 아니라 **암기**(overfitting)일 수 있으니까요. ([FAQ Q3](../01-basics/07-헷갈림-FAQ.md))

## 레벨 3 — 모델: 사실은 커닝페이퍼 한 장

bigram = "**직전 글자 1개만** 보고 다음 글자를 찍는" 세상에서 제일 단순한 모델.

모델의 전부가 **표 한 장**입니다:

```
        다음에 'a'  'b'  'c' ... 가 올 점수
현재 'q'  [  0.1  0.3  0.2  ...  9.8 ('u' 자리!) ]   ← q 다음엔 u가 온다는 걸 학습한 상태
현재 'z'  [  ...                                 ]
  ...
```

```python
nn.Embedding(vocab_size, vocab_size)   # 이게 그 표. 세로도 vocab개, 가로도 vocab개
```

**학습이란 = 이 표의 숫자들을 조금씩 고쳐나가는 것.** 처음엔 무작위 숫자로 가득하지만, 수천 번 고치고 나면 'q' 행의 'u' 자리 점수가 저절로 높아져 있습니다. (감동 포인트!)

출력 모양: `(B, T, C)` = 배치 B개 × 위치 T개 × 각 위치마다 vocab C개의 점수.
이 shape 3형제에 익숙해지는 게 tiny 프로젝트의 절반입니다. 헷갈리면 이렇게 읽으세요:
> "문제지 **B**장을, 각 장엔 글자 **T**개가 있고, 글자마다 **C**개 후보의 점수가 붙어 있다."

## 레벨 4 — Loss: "얼마나 놀랐나"의 평균

**cross-entropy loss = -ln(모델이 정답 글자에 준 확률)** 을 모든 자리에서 평균 낸 것.

[수학 문서](../01-basics/04-최소한의-수학.md)의 일기예보 비유 그대로입니다 — **틀린 예보관일수록 크게 놀랍니다.**

| 정답에 준 확률 | loss | |
|---|---|---|
| 0.9 | 0.11 | 확신하고 맞힘 (좋은 예보관) |
| 0.25 | 1.39 | 4지선다 찍기 |
| 0.01 | 4.61 | 사실상 몰랐음 |

**실전 체크포인트 3개 (외우세요)**:
1. **시작 loss ≈ ln(vocab)**. vocab이 65면 4.17. 크게 다르면 **버그입니다.**
   (아무것도 모르는 모델은 65개 후보에 확률을 똑같이 1/65씩 나눠주니까)
2. loss가 **뚝뚝 떨어지다 완만해지는** 곡선이 정상입니다.
3. train은 내려가는데 **val이 올라가기 시작 = 암기(overfitting) 시작점**.

**loss가 안 떨어지면 의심하는 순서** (8주차 관문 질문):
learning rate(너무 큼→튀거나 NaN, 너무 작음→제자리) → 데이터(배치를 decode해서 눈으로 확인!) → `zero_grad()` 빠뜨림 → 모델이 너무 단순함.

## 레벨 5 — Optimizer: 무엇을 고치는가

**optimizer가 고치는 것은 "모델의 파라미터"** 입니다. (데이터도 아니고, loss 공식도 아닙니다 — 면접 함정 질문!)
bigram에선 곧 **레벨 3의 표에 적힌 숫자들**이죠.

```python
loss.backward()        # ① 표의 각 칸을 "어느 쪽으로 밀면" loss가 줄지 자동 계산
optimizer.step()       # ② 그 방향으로 learning_rate만큼 한 걸음 밀기
optimizer.zero_grad()  # ③ 계산해둔 방향 메모를 지우기 (안 지우면 다음 번에 겹쳐 쌓임!)
```

- **SGD** = 순수한 "안개 속 산 내려가기". **AdamW** = 파라미터마다 걸음 크기를 알아서 조절해주는 개량판 (우리가 쓸 것, 요즘 표준)
- **learning rate 실험(6주차)**: 기본값 1e-2에서 ×10 하면? ÷100 하면? 곡선 3개를 그려 비교합니다.

## 레벨 6 — Sampling: 확률에서 진짜 글자로

학습이 끝난 모델로 글을 쓰는 법 — **"점수표 보고 → 확률로 바꾸고 → 제비뽑기"의 반복**입니다:

```
반복:
  지금까지 쓴 글 → 모델 → 마지막 자리의 점수들 (C개)
  → 점수 ÷ temperature       (온도 조절)
  → softmax                  (점수 → 확률, 합이 1)
  → 확률대로 제비뽑기         (torch.multinomial)
  → 뽑힌 글자를 뒤에 붙이고 다시 반복
```

- **temperature가 조절하는 것 = 제비뽑기의 과감함**
  - T→0: 1등만 뽑음 (안전하지만 같은 말 반복 위험)
  - T=1: 배운 대로
  - T>1: 꼴찌도 뽑힐 수 있음 (창의적이지만 헛소리 위험)
- **왜 1등을 안 뽑고 제비뽑기를 하나?** 늘 1등만 뽑으면 매번 똑같은 문장만 나옵니다. 약간의 운을 섞어야 글이 다양해져요.
- **gongo-rag와 연결**: RAG 답변에 낮은 temperature(0.2)를 쓰는 이유를 이제 **코드 수준에서** 압니다 — 공고문 안내에 창의력은 필요 없으니까!

## 레벨 7 — bigram의 한계 → attention의 예고

학습을 끝낸 bigram의 생성물은 "그럴듯해 보이는 글자 조합의 헛소리"입니다. loss도 2.5쯤에서 더는 안 내려가요. **당연합니다 — 직전 1글자만 보니까.**

```
"그 회사는 3년 전에 설립됐다. 따라서 신청 자격이 ___"
                                          ↑ bigram이 보는 건 "이" 한 글자뿐!
```

"**멀리 있는 문맥을 어떻게 볼 것인가**"의 답이 attention입니다 → [어텐션-개념.md](어텐션-개념.md)
