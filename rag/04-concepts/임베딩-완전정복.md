## 레벨 0 — 복습: "검색"이 뭐였더라

검색 = **① 모든 문서에 점수를 매기고(채점) → ② 점수 순으로 줄 세워(정렬) → ③ 상위 k개를 내놓기.** BM25에서 직접 만든 그 `search`가 검색의 정의 그 자체였습니다.

남은 질문은 딱 하나: **"채점을 어떻게 하나?"** BM25는 "글자가 겹치나"로 채점했습니다. 임베딩은 여기를 바꿉니다 — **"뜻이 비슷한가"**로. 나머지(줄 세우기, 상위 k개)는 **완전히 똑같습니다.**

## 레벨 1 — BM25의 벽 (직접 본 것)

BM25는 `tokens.count(단어)`로 채점했죠 — **글자가 똑같이 있어야만** 셉니다. 그래서 두 가지를 못 합니다:

**① 없는 글자는 0점** — 테스트에서 "김치찌개"로 검색했을 때 세 문서 다 **0.000** 나왔죠. 겹치는 글자가 없으니까요.

**② 뜻은 같은데 글자가 다르면 놓침** — 이게 진짜 문제입니다:

```
질문:  "보조금 얼마야?"
문서:  "지원금 1억원 지급"     ← 사람 눈엔 정답! 근데...
```

BM25는 `.count("보조금")`으로 문서를 뒤지는데, 문서엔 "지원금"이라 적혀 있어 "보조금" 글자가 없습니다 → **0점.** **정답을 눈앞에 두고 0점**을 주는 거죠. 이게 BM25의 벽입니다.

## 레벨 2 — 아이디어: 뜻을 "좌표"로 바꾸자

만약 단어를 **뜻이 담긴 숫자 좌표**로 바꿀 수 있다면?

```
(상상용 3칸짜리 예시)
            [돈 관련,  정부 관련,  동물 관련]
지원금  →  [ 0.9,      0.8,       0.0 ]
보조금  →  [ 0.9,      0.7,       0.1 ]   ← 지원금과 거의 같은 자리! (뜻이 비슷하니까)
고양이  →  [ 0.0,      0.0,       0.9 ]   ← 멀리 떨어진 자리
```

"보조금"과 "지원금"은 **글자는 다르지만 좌표가 이웃**입니다. 그럼 "글자 겹침" 대신 **"좌표가 가까운가"**로 채점하면 — 뜻이 같은 걸 찾아낼 수 있습니다. 이게 임베딩이 존재하는 **단 하나의 이유**입니다.

> 이 좌표는 어디서 오나? 대량의 글을 학습한 모델이 "비슷한 자리에 쓰이는 말은 가까운 좌표"가 되도록 만들어둔 겁니다. tiny pretraining의 embedding layer가 이걸 미니 버전으로 학습해요 (레벨 7 연결고리).

## 레벨 3 — 좌표 두 개를 어떻게 비교? → cosine

좌표가 "가까운지"를 재는 자가 **코사인 유사도(cosine)**입니다. 핵심 성질 두 개만:

1. **항상 두 개를 받습니다.** 자로 뭘 잰다면 늘 두 점 사이를 재죠. `cosine(A, B)` — A 하나만 넣으면 "뭐랑 비교하라고?" 에러입니다.
2. **방향이 비슷한 정도**를 -1~1로 돌려줍니다. 같은 방향이면 1, 무관하면 0.

당신이 이미 만든 함수예요:
```python
cosine = (a·b) / (|a| × |b|)      # 내적 ÷ (a크기 × b크기)
```

손계산으로 확인했던 것: `cosine([3,4],[6,8]) = 1.0` (같은 방향), `cosine([3,4],[4,-3]) = 0.0` (직각=무관). 🎮 놀이터에서 벡터를 드래그하면 이 값이 실시간으로 변합니다.

## 레벨 4 — 근데 진짜는 768차원? (겁먹지 마세요)

레벨 2의 예시는 3칸이었지만, 실제 모델은 **768칸짜리** 좌표를 만듭니다:

```
"보조금 얼마야?" → [0.11, -0.56, 0.91, ... (768개) ...]
```

왜 768개냐 — 이 모델이 뜻을 768개 축으로 표현하도록 학습됐기 때문(당신이 정한 게 아니라 모델이 정한 값). **상상은 안 되지만 계산은 3칸과 똑같습니다.** cosine 공식은 칸이 3개든 768개든 "다 곱해서 더하고, 크기로 나눈다"로 동일해요.

> ⚠️ 그래서 당신 cosine 함수의 `a[0]*b[0] + a[1]*b[1]`은 **2칸만** 더해서, 손계산 예제(2차원)는 통과하지만 진짜 768차원엔 부족합니다. 이때 numpy 한 줄 `np.dot(a,b) / (np.linalg.norm(a) * np.linalg.norm(b))`로 바꾸면 칸이 몇 개든 알아서 다 더해줍니다. (먼저 2칸 버전으로 원리를 이해하고 → numpy로 바꿔 차원 무관하게 만드는 게 추천 순서)

## 레벨 5 — 글자를 좌표로: embed_texts가 해주는 것

문장을 좌표로 바꾸는 건 **모델의 일**이라 배관으로 제공됩니다 (`embed_texts`). 규칙은 딱 하나 — **넣은 문장 수 = 나온 좌표 수**:

```
문장 1개 넣으면 →  shape (1, 768)    좌표 1줄
문장 3개 넣으면 →  shape (3, 768)    좌표 3줄
                       ↑        ↑
                   문장 수    각 좌표는 768칸
```

그래서 힌트 1이 왜 그 모양인지 풀립니다:
```python
q_vec = embed_texts([query])[0]
                    └──┬──┘ └┬┘
                       │     └ [0]: (1,768)에서 좌표 하나 빼내기 → (768,)
                       └ 질문을 리스트에 담아 넣기 (embed_texts는 리스트를 받으니까)
```

## 레벨 6 — 검색 조립: BM25와 뼈대가 똑같다

이제 부품이 다 모였습니다. 임베딩 search는 BM25 search와 **딱 두 줄만** 다릅니다:

| 덩어리 | BM25 (완성함) | 임베딩 |
|---|---|---|
| 질문 준비 | `self.tokenizer(query)` | `embed_texts([query])[0]` |
| 빈 통 | `results = []` | **똑같음** |
| 문서마다 채점 | `self.score(...)` | `cosine_similarity(q_vec, chunk_vectors[i])` |
| 성적표 적기 | `results.append((i, s))` | **똑같음** |
| 줄 세우기 | `sorted(...)[:k]` | **똑같음** |

채점 도구(글자겹침 → 좌표비교)와 질문 준비(토큰 → 좌표)만 바뀌고, **빈 통·반복·정렬은 어제 짠 것 그대로**입니다. "질문 좌표는 고정, 문서 좌표만 하나씩 바꿔가며 cosine 재기" — 이게 반복문이 하는 일입니다.

## 레벨 7 — 현실 함정: 임베딩이 무조건 최고는 아니다 (직접 본 것)

데모에서 "보조금" 질문에 "지원금" 문서가 **1위가 아니라 꼴찌**로 나온 적 있죠. 교과서와 반대였습니다. 왜?

- **문서가 너무 짧고 데이터가 적으면** 좌표가 불안정합니다. "지원금 1억원 지급"은 거의 단어 수준이라, 문장용 모델이 뜻을 제대로 못 잡아요. 진짜 공고문(문단 단위, 수십 개)에선 훨씬 안정적입니다.

그래서 결론은 "임베딩 > BM25"가 **아닙니다.** 서로 강점이 반대예요:

| 질문 유형 | 예 | 이기는 쪽 | 이유 |
|---|---|---|---|
| 말은 다른데 뜻이 같음 | "돈 얼마 주나요?" | **임베딩** | 뜻(좌표)으로 연결 |
| 정확한 키워드·고유명사·숫자 | "청년창업사관학교 15기" | **BM25** | 임베딩은 "15기"를 "14기"랑 헷갈림 |
| 흔한 단어뿐인 짧은 질문 | "신청 방법" | 애매 | 둘 다 약함 |

> **그래서 실무는 둘을 합칩니다** (= hybrid search, W7). 어느 하나가 이기는 게 아니라 약점을 서로 메우는 것 — 이게 "BM25랑 임베딩 차이가 뭐예요?"에 대한 **면접 만점 답**입니다. W6 실험에서 당신의 골든셋으로 위 표를 직접 검증하고, 예상과 다른 칸을 찾는 게 하이라이트예요.

## 심화 노트 (지금은 훑고, 필요할 때 다시)

**실무 함정**
- **질문과 문서는 같은 모델로 임베딩해야** 합니다 (다른 모델 좌표끼리 비교는 무의미). 캐시에 모델명을 함께 저장.
- **chunk가 너무 길면** 여러 주제가 한 좌표에 뭉개져 "회색 벡터"가 됩니다 → chunk size 실험과 연결.
- **정규화**: 좌표를 길이 1로 맞춰두면 cosine = 내적이 되어 계산이 단순해집니다 ([FAQ Q9](../01-basics/07-헷갈림-FAQ.md)).

**tiny pretraining과의 연결 (면접 킬러 멘트)**
> "gongo-rag에선 완성된 임베딩 모델을 검색에 **사용**했고, tiny pretraining에선 embedding layer가 무작위에서 시작해 학습으로 의미를 갖는 과정을 **직접 관찰**했습니다. 그래서 임베딩이 마법의 블랙박스가 아니라 학습의 산물이라는 걸 코드 수준에서 이해합니다."
