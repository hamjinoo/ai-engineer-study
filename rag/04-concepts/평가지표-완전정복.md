## 레벨 0 — 왜 점수를 매기나

내 검색기를 고쳤습니다. **좋아진 걸까요?**

"음… 몇 개 검색해보니 괜찮은 것 같은데요?" — 이건 답이 아닙니다. 느낌은 기억이 조작하고, 잘 된 3개만 눈에 들어오니까요.

> **핵심**: 숫자가 없으면 "고쳤다"고 말할 수 없습니다. 그리고 숫자가 없으면 **실험도 못 합니다.**
> chunk를 500자로 할지 800자로 할지, BM25를 쓸지 임베딩을 쓸지 — 전부 "어느 쪽 점수가 높나"로만 결정할 수 있어요.

그래서 **시험지(골든셋)**를 만들고 **채점기(evaluate.py)**를 만드는 겁니다.

## 레벨 1 — 내 지표: hit@k (아주 쉬움)

**hit@k** = 검색기가 가져온 **상위 k개 안에 정답이 들어 있으면 1점**, 없으면 0점. 그걸 전체 문제로 평균 낸 것.

```
질문 30개짜리 시험지, k=3 (상위 3개만 본다)

  q1: 상위 3개 안에 정답 있음  → ⭕
  q2: 상위 3개 안에 정답 있음  → ⭕
  q3: 상위 3개 다 엉뚱함       → ❌
  ... (30문제)

  30문제 중 24개 성공  →  hit@3 = 24/30 = 0.8
```

끝입니다. 이게 여러분이 `hit_rate_at_k`로 구현할 전부예요. **그런데** 면접관은 이 말을 안 씁니다. 면접관의 공용어는 다음 레벨에 나오는 **precision / recall** 이에요. 그래서 번역을 배워야 합니다.

## 레벨 2 — 그물 비유: precision과 recall

**바다에 물고기(정답)가 있고, 나는 그물(검색기)을 던집니다.**

```
        바다 전체
   ┌─────────────────────┐
   │  🐟        🐟       │      🐟 = 진짜 정답 (바다에 2마리)
   │   ┌────────────┐    │
   │   │ 🐟 🥾 🥫  │    │      내 그물에 잡힌 것 3개:
   │   └────────────┘    │        🐟 1마리 + 🥾장화 + 🥫깡통
   │      내 그물         │
   └─────────────────────┘
```

여기서 **완전히 다른 두 가지 질문**을 할 수 있습니다:

| 지표 | 질문 | 계산 | 위 그림 |
|---|---|---|---|
| **Precision (정밀도)** | 내가 **건진 것 중** 진짜는 몇 %? | 진짜 / 내가 건진 것 | 1/3 ≈ **0.33** |
| **Recall (재현율)** | **바다의 진짜 중** 내가 건진 건 몇 %? | 내가 건진 진짜 / 바다의 진짜 전부 | 1/2 = **0.50** |

**외우는 법**: 🖐️ **P는 내 손 안(그물 안)을 보고, R은 바다 전체를 본다.**

그래서 낮으면 이런 뜻입니다:
- **Precision이 낮다** = 쓰레기(장화·깡통)를 잔뜩 건졌다 → LLM 프롬프트에 **노이즈**가 들어가서 답이 흐려짐
- **Recall이 낮다** = 물고기를 놓쳤다 → 답에 필요한 **근거 자체가 없음** → LLM이 지어내기 시작

## 레벨 3 — 둘은 왜 서로 잡아먹나 (k가 그 손잡이)

그물을 **크게** 만들면 어떻게 될까요?

```
k=1  (아주 작은 그물)
     → 딱 1개만 건짐. 그게 진짜일 확률은 높음 (P 높음 👍)
     → 근데 바다의 물고기 2마리 중 최대 1마리만 가능 (R은 아무리 잘해도 0.5 👎)

k=10 (아주 큰 그물)
     → 물고기 2마리가 다 들어올 가능성 큼 (R 높음 👍)
     → 근데 10개 중 8개는 장화와 깡통 (P 낮음 👎)
```

> **k는 recall을 사고 precision을 파는 손잡이입니다.**

실험④("top-k를 키우면 무조건 좋아지는가?")의 정체가 바로 이겁니다. 검색 recall은 계속 오르는데, 프롬프트에 쓰레기가 늘어 **생성 품질이 꺾이는 지점**이 있어요. 그 지점을 내 데이터에서 찾는 게 실험입니다.

## 레벨 4 — F1: 둘 다 잘해야만 점수를 주는 심판

P와 R을 하나의 숫자로 합치고 싶습니다. 그냥 평균 내면 될까요? **안 됩니다:**

```
극단 사례: 그물로 딱 1마리 건졌는데 진짜였음. 근데 바다엔 물고기가 100마리.
  P = 1/1 = 1.00   (건진 것 중 100% 진짜!)
  R = 1/100 = 0.01 (99마리를 놓침)

  그냥 평균(산술평균) = (1.00 + 0.01) / 2 = 0.505   ← "절반은 한다"?! 거짓말입니다.
  F1 (조화평균)      = 2×1.00×0.01 / (1.00+0.01) ≈ 0.02   ← 실체를 반영 ✅
```

**F1 = 2PR/(P+R)** — 이걸 조화평균이라 부르는데, 이름은 잊어도 되고 **성질 하나만** 기억하세요:

> 🎯 **조화평균은 둘 중 낮은 쪽에 끌려간다.** = 둘 다 좋아야만 높아진다.
> (한 과목만 100점이고 다른 과목 0점인 학생에게 "평균 50점"이라고 후하게 쳐주지 않는 심판)

레벨 2의 그물로: P=1/3, R=1/2 → F1 = 2×(1/6)÷(5/6) = **0.4**.

## 레벨 5 — 그래서 내 hit@k는 표준어로 뭐라고?

| 내 지표 | 표준 언어로 번역 |
|---|---|
| **hit@k** | 우리 골든셋은 질문당 정답 근거가 **1개**입니다. 바다에 물고기가 1마리인 셈이죠. 그럼 "그 1마리를 건졌나?"가 곧 recall이므로 → **hit@k = recall@k**. 면접에서 이렇게 말하면 정확합니다. |
| **MRR** (선택 확장) | 정답이 **몇 등으로** 나왔는지까지 봅니다. 질문마다 1/(정답 등수)의 평균. 예: 세 질문에서 정답이 1등, 2등, 실패 → (1 + 0.5 + 0)/3 = 0.5. hit@3이 똑같아도 "1등으로 딱 찾아주는 검색기"를 구분해줌 → reranking이 필요한지 판단하는 근거(관문질문 8번) |
| **accuracy의 함정** ⚠️ | 골든셋 35문항 중 답 없는 문제(no_answer)가 5개뿐이라면, **무조건 "답 있음"이라고 우겨도** 정확도 30/35 = 86%! 숫자는 높은데 실력은 0입니다. **한쪽으로 기울어진 데이터에서 accuracy는 거짓말을 합니다** → 그래서 유형별로 나눠서 평가하는 것 |

## 레벨 6 — RAG 실패를 지표 언어로 번역 (이 문서의 핵심)

8주차에 쓸 실패 분류표를 이 언어로 다시 쓰면, **면접 답변이 저절로 완성됩니다:**

| RAG 증상 | 지표 언어 | 처방 |
|---|---|---|
| 정답 조각이 top-k에 아예 없음 (검색 실패) | **recall 실패** (물고기를 놓침) | k↑, hybrid, 형태소 분석, chunking 개선 |
| 엉뚱한 조각이 섞여 답이 흐려짐 | **precision 실패** (장화를 건짐) | k↓, reranking, chunk 정제 |
| 답 없는 질문에 지어냄 (환각) | **precision 실패의 극단** | 프롬프트 규칙, 인용 검증, no_answer 평가 |
| 답이 있는데 "정보 없음"이라 함 | 생성이 너무 소심함 (**recall 방향** 손실) | 프롬프트 완화, 근거 포맷 개선 |

**면접 문장 뼈대** (이 문서를 읽은 값어치):
> "검색은 hit@3 — 우리 골든셋에선 사실상 recall@3 — 으로 측정했습니다. 다만 recall만 보면 환각을 못 잡기 때문에, 답 없는 질문 5개를 넣어 precision 방향(지어내지 않는가)을 함께 평가했습니다. top-k 실험에서는 k가 recall을 사고 precision을 파는 트레이드오프라는 걸 제 데이터로 직접 확인했습니다."

## 레벨 7 — evaluate.py에 걸어두기 (선택 과제)

- `hit_rate_at_k` 결과에 **MRR 추가**해보기 (정답 조각의 등수를 이미 알고 있으니 10줄이면 됩니다)
- 실험 기록표에 hit@3와 MRR을 나란히 두면 → "재현율은 같은데 순위 품질이 다르다"는 **고급 관찰**이 가능해집니다
