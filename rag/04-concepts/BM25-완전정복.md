# BM25 완전정복 — 점수 계산기를 5번 업그레이드하는 이야기

> 읽는 시점: Week 3, `src/bm25.py` 구현 **직전**. 이 문서의 손계산 예제가 곧 여러분 코드의 채점 기준입니다.
> 🎮 [놀이터.html의 BM25 계산기](../놀이터.html#bm25)에서 k1·b를 움직이며 이 손계산을 라이브로 볼 수 있습니다.
> **읽는 법**: 레벨 1부터 순서대로. 각 레벨은 **"지금 계산기의 사고 장면 → 고치는 부품 → 고친 후 점수가 어떻게 바뀌나"** 순서입니다. 계산기 앱을 옆에 켜두고 숫자를 따라 눌러보세요 — 눈으로만 읽으면 남지 않습니다.

## 레벨 0 — 검색이란 결국 "점수 매겨 줄 세우기"

질문이 들어오면 → 모든 chunk에 **관련도 점수**를 매긴다 → 점수 순으로 줄 세워 상위 k개를 돌려준다. 검색의 전부입니다. 남은 문제는 단 하나, **"점수를 어떻게 계산하나?"** — BM25는 이 계산기를 30년간 다듬은 결과물이고(엘라스틱서치 기본값), **학습이 필요 없습니다.** 세기만 하면 돼요.

레벨 1~3에서 계속 쓸 연습 문제입니다 (문서 길이는 레벨 4 전까지 무시):

```
질문: "청년 지원 금액"

문서 A: "지원 안내 지원 절차 지원 방법 지원 문의"   ← '지원' 도배 문서
문서 B: "청년 지원 금액 안내"                       ← 진짜 정답 문서
문서 C: "청년 주택 정책"                            ← 낚시 문서
```

사람 눈에는 당연히 B가 1등이어야 합니다. 계산기가 그렇게 판단하는지 봅시다.

## 레벨 1 — TF: "많이 나오면 관련 있다"

가장 순진한 계산기: **질문 단어가 문서에 등장한 횟수를 전부 더한다.** (이 횟수가 TF)

| 문서 | 계산 | 점수 | 순위 |
|---|---|---|---|
| A | 지원×4 | **4** | 🥇 ← ??? |
| B | 청년 1 + 지원 1 + 금액 1 | 3 | 2위 |
| C | 청년 1 | 1 | 3위 |

**🚨 사고 발생: 도배 문서 A가 1등.** '지원'만 반복한 문서가, 질문의 세 단어를 모두 가진 B를 이겼습니다.

원인을 뜯어보면 두 가지입니다:
1. 흔한 단어('지원')와 귀한 단어('금액')를 **똑같이 1점**으로 쳤다 → **레벨 2**가 고칩니다
2. 같은 단어 4번 등장을 **4배** 가치로 쳐줬다 → **레벨 3**이 고칩니다

## 레벨 2 — IDF: 단어마다 "몸값"을 다르게

직관: **어디에나 있는 단어는 정보가 없다.** "벌점을 준다"기보다 정확한 그림은 — 모든 단어의 등장에 **몸값(가중치)을 곱하는데, 흔한 단어일수록 몸값이 싼 것**입니다.

몸값 공식 (IDF):

```
idf(t) = ln( (N − df + 0.5) / (df + 0.5) + 1 )

N     = 전체 문서 수
df(t) = 단어 t가 "등장하는 문서"의 수  ⚠️ 한 문서에 4번 나와도 1로 셉니다!
(+0.5와 +1은 0으로 나누기/음수 방지용 안전장치 — 이대로 구현하면 됩니다)
```

우리 코퍼스(N=3)로 몸값 계산 — 계산기로 직접 눌러보세요:

| 단어 | 어느 문서에 있나 | df | 계산 | 몸값 |
|---|---|---|---|---|
| 지원 | A, B | 2 | ln(1.5/2.5 + 1) = ln(1.6) | **0.47** |
| 청년 | B, C | 2 | 동일 | **0.47** |
| 금액 | B만 | 1 | ln(2.5/1.5 + 1) = ln(2.67) | **0.98** ← 희귀해서 몸값 2배! |

**업그레이드된 점수 = Σ (등장 횟수 × 몸값)**:

| 문서 | 계산 | 점수 | 순위 |
|---|---|---|---|
| A | 4 × 0.47 | 1.88 | 2위 |
| B | 1×0.47 + 1×0.47 + 1×0.98 | **1.92** | 🥇 역전! |
| C | 1 × 0.47 | 0.47 | 3위 |

**그래서? — IDF가 하는 일**: 흔한 단어의 점수 인플레를 걷어내고, 질문의 진짜 핵심 단어('금액')가 승부를 결정하게 만듭니다.

…그런데 1.92 vs 1.88, 겨우 0.04 차이로 이겼습니다. A가 '지원'을 **한 번만 더** 썼다면(5번) 다시 역전당해요. 도배가 여전히 위협적입니다 → 레벨 3.

## 레벨 3 — 포화: 반복의 가성비 깎기

직관: '지원' 0번과 1번의 차이는 큽니다(없다 vs 있다). 하지만 3번과 4번의 차이는? 거의 없죠. 그런데 지금 계산기는 4번을 1번의 **4배**로 쳐줍니다. 그래서 등장 횟수 f를 그대로 쓰지 않고 이렇게 눌러줍니다:

```
포화(f) = f × (k1+1) / (f + k1)        (k1 = 1.5가 표준)
```

f에 숫자를 넣어보면 (계산기로 확인!):

| 실제 횟수 f | 포화 후 가치 |
|---|---|
| 1 | 1.00 |
| 2 | 1.43 |
| 4 | 1.82 |
| 10 | 2.17 |
| 100 | 2.46 |

아무리 반복해도 **k1+1 = 2.5를 넘지 못하는 상한**이 생깁니다. 2번째까지는 값을 꽤 쳐주고(1→1.43), 그 뒤로는 급격히 짜집니다. (k1이 크면 늦게 포화 = 반복을 더 믿어줌 — 🎮 놀이터에서 k1 슬라이더로 확인)

**업그레이드된 점수 = Σ (몸값 × 포화(f))**:

| 문서 | 계산 | 점수 | 순위 |
|---|---|---|---|
| A | 0.47 × 포화(4) = 0.47 × 1.82 | 0.85 | 2위 |
| B | (0.47 + 0.47 + 0.98) × 포화(1) | **1.92** | 🥇 |
| C | 0.47 × 1.00 | 0.47 | 3위 |

이제 B가 **2배 이상** 차이로 이깁니다. A가 '지원'을 100번 도배해도 0.47×2.46 = 1.16이 상한이라 절대 못 따라옵니다.

**그래서? — 포화가 하는 일**: 도배로 점수를 무한정 벌 수 없게 **상한**을 만듭니다.

## 레벨 4 — 길이 보정: 긴 문서의 반칙 막기

마지막 헛점: 30페이지짜리 잡탕 문서는 온갖 단어를 **우연히** 다 담고 있습니다. 생각해보세요 —

> 5단어 문서에서 '금액' 1번 = 그 문서의 핵심 주제
> 500단어 문서에서 '금액' 1번 = 스쳐 지나간 언급

같은 "1번"인데 가치가 다릅니다. 처방: 포화 공식 분모의 k1을 문서 길이에 따라 늘리거나 줄입니다:

```
분모의 k1  →  k1 × (1 − b + b × |D| / avgdl)

|D|   = 이 문서의 토큰 수,  avgdl = 전체 평균 토큰 수
b     = 보정 강도 (0~1, 표준 0.75. b=0이면 보정 꺼짐)
```

효과를 숫자로 — **같은 "1번 등장"의 가치**가 문서 길이에 따라 (k1=1.5, b=0.75):

| 문서 길이 | 1번 등장의 가치 |
|---|---|
| 평균의 절반 | **1.29** (더 쳐줌 — 짧은 문서의 등장은 진하다) |
| 딱 평균 | 1.00 |
| 평균의 2배 | **0.69** (깎음 — 길면 얻어걸렸을 확률↑) |

**그래서? — 길이 보정이 하는 일**: 긴 잡탕 문서가 "얻어걸린 등장"들로 점수를 쓸어가는 것을 막습니다. (🎮 놀이터에서 b를 0으로 내려보세요 — 짧은 문서의 이점이 사라지는 게 보입니다)

## 레벨 5 — 완성: 부품 조립

이제 부품을 전부 겹쳐 쓰면 BM25입니다. 질문 Q의 각 단어 t마다 계산해서 **합산**:

```
score(D, Q) = Σ   IDF(t) × f × (k1+1) / ( f + k1×(1 − b + b×|D|/avgdl) )
             t∈Q  └레벨2┘  └───레벨3 (분자)───┘   └────레벨4 (분모 보정)────┘
```

겁먹지 마세요 — **레벨 2, 3, 4를 한 줄에 포갠 것**뿐입니다. 새로운 내용은 없습니다.

## 🖐️ 최종 시험 — 손계산 예제 (이게 여러분 코드의 채점 기준)

이번엔 실전 코퍼스입니다 (토큰은 공백 분리, k1=1.5, b=0.75, **이제 길이도 계산**):

```
D1: "청년 창업 지원 사업 공고"      (길이 5)
D2: "창업 기업 지원 금액 안내"      (길이 5)
D3: "청년 주택 정책 안내"          (길이 4)
질문 Q: "청년 지원 금액"
```

**① df 세기**: N=3. df(청년)=2 (D1,D3), df(지원)=2 (D1,D2), df(금액)=1 (D2)

**② 몸값(IDF)** — 레벨 2와 같은 df라서 값도 같습니다:
```
IDF(청년) = ln(1.6)   ≈ 0.470
IDF(지원) = ln(1.6)   ≈ 0.470
IDF(금액) = ln(2.667) ≈ 0.981
```

**③ avgdl** = (5+5+4)/3 ≈ 4.667

**④ D2 점수** (지원 f=1, 금액 f=1, 청년 없음, |D|=5):
```
길이보정 분모 = 1.5 × (0.25 + 0.75×5/4.667) = 1.5 × 1.0536 ≈ 1.580
1번 등장의 가치 = 1×2.5 / (1+1.580) ≈ 0.969
score(D2) = 0.470×0.969 + 0.981×0.969 ≈ 0.455 + 0.951 = 1.406
```

**⑤ 전체 결과**:
```
D2 ≈ 1.41  >  D1 ≈ 0.91  >  D3 ≈ 0.50
```

D1은 질문 단어를 2개(청년, 지원)나 갖고도 D2에 집니다 — **희귀 단어 '금액'의 몸값이 승부를 갈랐습니다.** 레벨 2에서 본 그 원리 그대로죠.

## 요약 — "그래서?"에 대한 답 한 장

| 부품 | 사고 장면 | 그래서 (처방) |
|---|---|---|
| **TF** | 도배 문서가 1등 | "몇 번 나왔나"는 출발점일 뿐 — 아래 셋으로 교정 |
| **IDF** | 흔한 단어와 귀한 단어가 같은 1점 | 단어마다 **몸값**을 곱한다 — 희귀할수록 비싸게 |
| **포화 (k1)** | 4번 등장 = 4배 가치 | 반복의 가성비를 깎아 **상한(k1+1)** 을 만든다 |
| **길이 보정 (b)** | 긴 잡탕 문서가 얻어걸림 | 평균보다 길면 깎고, 짧으면 더 쳐준다 |

## 증명 코너 — "이 식이 정말 약속대로 작동하나?" (사칙연산만으로)

BM25는 수학 정리가 아니라 **공학 설계**입니다. 그래서 "전체 식 증명" = 부품 4개가 각각 약속을 지키는지 확인하는 것 — 전부 사칙연산과 "분모가 크면 몫이 작다" 하나로 됩니다:

1. **포화 상한** — 등장 가치 = f/(f+k1) × (k1+1). 앞 분수는 "어떤 수 ÷ 그보다 k1 큰 수"라 **항상 1 미만** → 전체는 항상 (k1+1) 미만. 도배해도 못 넘는 천장. ∎
2. **도배 무력화** — 몸값 w인 단어를 무한 도배해도 최고점은 w×(k1+1)로 고정. 이 상한이 상대 점수보다 낮으면 영원히 못 이김 (레벨 3의 A: 0.47×2.5=1.18 < B의 1.92). ∎
3. **흔할수록 몸값↓** — df가 1 커지면 분자(없는 문서 수)는 줄고 분모(있는 문서 수)는 늘어, 분수가 **양방향으로** 작아짐. ln은 순서를 안 바꾸는 버튼이므로 몸값도 반드시 하락 (N=3에서 df=1,2,3 → 0.98, 0.47, 0.13). ∎
4. **길수록 등장 가치↓** — 문서가 길어지면 분모의 길이 배율만 커지고 분자는 그대로 → 몫 하락 (평균의 ½/1/2배 → 1.29/1.00/0.69). ∎
- 보너스: 공식 끝의 +1이 ln 입력을 항상 1보다 크게 만들어 **몸값은 절대 음수가 안 됨**. ∎

조립: 전체 점수 = Σ(양수 몸값 × 등장 가치) — 양수 곱하기와 더하기는 위 성질을 깨지 않으므로 전체도 성립.

> "왜 하필 이 모양의 식인가?"는 증명이 아니라 **실험의 영역**입니다 — 30년간 검색 벤치마크에서 살아남아 표준이 된 것. 여러분이 W6에 hit@k로 하는 검증과 같은 종류의 경험적 검증이며, 면접에서 이 구분을 말할 수 있으면 상위권 답변입니다.

## 한국어 함정 — 형태소 분석이 필요한 이유 (Week 6 실험)

공백 분리 tokenizer의 문제:

```
질문:  "지원금액은 얼마인가요"  → [지원금액은, 얼마인가요]
문서:  "지원 금액: 5천만원"     → [지원, 금액:, 5천만원]
→ 겹치는 토큰 0개. BM25 점수 0. 검색 실패!
```

한국어는 조사가 붙어 같은 단어가 수십 가지 표면형을 가집니다 (지원금액은/이/을/의...). **형태소 분석기(kiwipiepy)** 로 자르면:

```
"지원금액은" → [지원, 금액, 은] → 조사 제거 → [지원, 금액]   ← 이제 매칭!
```

`bm25.py`에 kiwi용 tokenizer 자리를 만들어뒀습니다. 6주차에 전/후 hit@k를 비교하세요 — 한국어 RAG 포트폴리오에서 가장 설득력 있는 실험입니다.

## 더 나아가기 (Week 7): Hybrid Search

BM25와 임베딩의 순위를 결합하는 가장 쉬운 방법 — **RRF (Reciprocal Rank Fusion)**:

```
RRF점수(문서) = 1/(60 + BM25에서의 순위) + 1/(60 + 임베딩에서의 순위)
```

점수 크기가 서로 달라도(BM25는 0~수십, cosine은 0~1) **순위만 쓰므로** 안전합니다. 60은 관례적 상수. 구현은 10줄이면 됩니다 — 실험⑤에서.
