# 어텐션 개념 — "필요한 곳만 골라 듣기" (직관편)

> 읽는 시점: Week 8~10 (계획서: 8주차 "attention 개념 진입", 9~12주차 "attention 기초 정리").
> 목표는 구현이 아니라 **"attention이 없으면 무엇이 어려운가"에 답하는 것** (12주차 관문).
> **좋은 소식**: 새로운 수학이 하나도 없습니다. 내적 + softmax — 둘 다 이미 배웠어요.

---

## 1. bigram이 부딪힌 벽 (직접 겪은 것)

여러분의 bigram은 **직전 글자 1개**만 봅니다. 그런데:

```
"그 회사는 3년 전에 설립됐다. 따라서 신청 자격이 ___"
                                            ↑
                              bigram이 보는 건 "이" 한 글자!
```

빈칸을 채우려면 저 멀리 앞에 있는 **"3년 전 설립"** 이 필요합니다. bigram에겐 불가능해요. 그래서 학습을 다 시켜도 헛소리만 뱉었던 겁니다.

**순진한 해결책**: "그럼 앞 글자들을 **전부 평균** 내서 주자!"
→ 안 됩니다. 중요한 것("3년")과 아무래도 좋은 것("그", "는")을 **똑같은 비중으로** 섞으면 다 뭉개져 버려요. 죽처럼.

> 교실에서 30명이 동시에 떠드는 소리를 평균 내면 → 그냥 소음입니다. **필요한 사람 말만 골라 들어야죠.**

## 2. 핵심 아이디어 — 칵테일 파티

> 🍸 **칵테일 파티 비유**: 시끄러운 파티장. 사람들이 사방에서 떠듭니다. 그런데 여러분은 **지금 필요한 사람의 목소리에만 귀를 집중**할 수 있죠. 나머지는 배경 소음으로 흘려보내고요.
> 심지어 **필요한 게 바뀌면 집중하는 대상도 바뀝니다.**

**attention = 지금 글자가, 앞선 글자들 각각에 "얼마나 귀를 기울일지" 가중치를 스스로 계산해서, 그 비율대로 정보를 섞어 오는 것.**

균등 평균(다 똑같이 듣기)이 아니라, **상황에 따라 달라지는 똑똑한 가중평균**입니다.

## 3. Q, K, V — 도서관 비유

각 글자가 세 가지 역할의 벡터를 만듭니다 (각각 학습되는 변환으로):

| | 도서관 비유 | 역할 |
|---|---|---|
| **Q**uery (질문) | 내가 사서에게 하는 질문 | "나는 지금 **어떤 정보가 필요한가**" |
| **K**ey (열쇠말) | 책등에 붙은 라벨 | "나는 **어떤 정보를 갖고 있다고 광고**하는가" |
| **V**alue (내용) | 책의 실제 내용 | "실제로 **넘겨줄 정보**" |

**절차 — 도서관에서 책 찾는 과정 그대로:**
```
1. 내 질문(Q)을 모든 책의 라벨(K)과 대조  → "얼마나 맞는가" 점수들   (내적!)
2. 점수를 softmax                        → 합이 1인 "집중도" 비율   (softmax!)
3. 그 비율대로 책 내용(V)들을 섞어 가져옴 → 내가 흡수한 문맥 정보
```

**미니 숫자 예**:
```
글자 A의 내용(V) = (1, 0)      글자 B의 내용(V) = (0, 1)
내 질문과의 맞음 점수: A에 2.2, B에 0.0

  → softmax(2.2, 0.0) ≈ (0.9, 0.1)     ← A에 90% 집중!
  → 흡수한 정보 = 0.9×(1,0) + 0.1×(0,1) = (0.9, 0.1)
                                          ↑ A의 정보를 주로 가져왔다
```

> 🎯 **이미 아는 것들로만 조립됐다는 점에 주목하세요.**
> **내적**(임베딩 검색에서 쓴 그 유사도!) + **softmax**(생성에서 쓴 그것!) + 가중평균.
> **새 수학이 하나도 없습니다.**

## 4. 눈치챘겠지만 — attention은 "검색"입니다

> Q = 질문, K = 색인, V = 문서 내용, 내적 = 유사도 점수, softmax 가중치 = 랭킹.

**여러분이 gongo-rag에서 만든 검색 파이프라인과 구조가 완전히 같습니다.** 차이는 단 두 개:

| | RAG 검색 (내가 코드로 만든 것) | attention (모델 안에서 벌어지는 것) |
|---|---|---|
| 어디서 | 문서 저장소 전체에서 | 문맥 창(context window) 안에서 |
| 어떻게 | 내가 짠 코드로, 명시적으로 | 학습된 가중치로, 매 글자마다 자동으로 |

이 대응을 스스로 말할 수 있으면 **두 프로젝트가 하나로 꿰집니다.** 계획서 9~12주차의 "gongo-rag의 embedding/token/context window와 연결해서 설명"이 바로 이것.

## 5. Transformer 조감도 (이름만 알면 됨)

```
글자 번호 → embedding(+위치 정보) → [ attention → FFN ] × N층 → 점수(logits)
```

- **multi-head**: attention을 여러 벌 **동시에** 돌립니다. (한 명은 문법 담당, 한 명은 지시어 담당… 역할 분담한 전문가 팀)
- **causal mask**: 미래 글자는 못 보게 **가림**. (커닝 방지 — 다음 글자 맞히기 시험인데 답을 보면 안 되죠!)
- **FFN**: 모아온 정보를 소화하는 작은 신경망 = [08-신경망-기초](../01-basics/08-신경망-기초.md)의 그 MLP.
- GPT/Claude = 이 블록을 **수십~수백 층 + 파라미터 수천억 개**로 키운 것. **원리는 여러분이 만든 것의 연장선입니다.**

## 6. 관문 질문 정면 대응

**"attention이 없으면 무엇이 어려운가?"** — 답에 넣을 3가지:
1. **멀리 있는 문맥을 못 본다** (bigram은 직전 1개, RNN도 길어지면 잊음) — 내 bigram 생성물이 헛소리였던 **직접 경험**을 근거로!
2. **균등 평균은 중요한 것과 잡음을 구분 못 한다** — attention은 **골라 듣는** 가중평균
3. 대명사 해소("그 회사"가 누구?), 조건 참조(공고문의 "위 1항의 경우") 같은 **실전 능력이 전부 여기서** 나옴

**"context window는 왜 유한한가?"** (꼬리질문 대비)
→ 모든 글자 쌍끼리 Q·K를 다 계산하므로, 글이 2배 길어지면 계산이 **4배**로 늡니다(길이의 제곱). 그래서 창 크기에 상한이 생겨요.
→ **그래서 RAG가 필요합니다!** 문서 전체를 창에 넣을 수 없으니, 관련 chunk만 골라 넣는 것.
> 🔄 **완벽한 순환 논리 완성**: attention의 한계 → RAG의 존재 이유. 면접에서 이걸 말하면 "아, 이 사람은 둘을 연결해서 이해하는구나"가 됩니다.

## 7. attention은 순서를 모른다 — 위치 정보 넣어주기

가중평균은 **섞기**입니다. 재료를 넣는 순서를 바꿔도 결과가 같죠. 즉 attention만으로는:

```
"창업 3년 이내"  와  "이내 3년 창업"  이 구분되지 않습니다! (순서 정보가 계산 어디에도 없으니까)
```

- **해결**: 자리마다(1번째, 2번째, …) **위치 벡터**를 만들어서 글자 벡터에 **더해줍니다.** 같은 단어라도 위치가 다르면 입력이 달라지니 순서가 살아나요. (자리마다 다른 색 스티커를 붙이는 것)
- 방식 이름만: 학습형 위치 임베딩(GPT-2), 사인파(원조 Transformer), **RoPE**(요즘 표준) — 면접에선 "위치 정보를 주입하는 방법들"로 묶어 말하면 충분.
- **bigram엔 왜 필요 없었나?** "직전 1개만 본다"는 구조 자체에 순서가 이미 들어 있었으니까요. **"전부 본다"로 바뀌는 순간 순서를 따로 줘야 합니다** — 이 대비가 가장 좋은 면접 답변입니다.

## 8. 같은 Transformer, 두 갈래 — BERT vs GPT

**여러분의 두 프로젝트가 정확히 이 두 갈래입니다:**

| | GPT 계열 (디코더) | BERT 계열 (인코더) |
|---|---|---|
| 보는 방향 | **왼쪽만** (미래는 가림) | **양쪽 다** (문장 전체를 한꺼번에) |
| 학습 목표 | 다음 글자 맞히기 | **빈칸** 맞히기 |
| 잘하는 것 | **생성** (글쓰기) | **이해·표현** (문장 → 벡터 하나) |
| 내 프로젝트에서 | tiny pretraining, RAG의 답변 생성 | gongo-rag의 임베딩 모델 (ko-sroberta) |

- "임베딩 모델과 생성 모델은 왜 다른 모델인가"([FAQ Q6](../01-basics/07-헷갈림-FAQ.md))의 구조적 답: **블록은 같고, 보는 방향과 학습 목표가 다릅니다.** 양쪽을 다 본 표현이 검색용 벡터에 유리하고, 한 방향으로 예측하는 구조가 글쓰기에 맞는 것.
- 💼 **면접 킬러 포지션**: "BERT 계열은 검색에 **사용**해봤고, GPT 계열은 미니 버전을 **직접 만들어**봤습니다." — 두 갈래를 다 만져본 신입은 드뭅니다.
