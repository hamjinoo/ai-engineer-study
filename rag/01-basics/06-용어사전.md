## 공통 (LLM 세계의 기본어)

| 용어 | 한 줄 정의 |
|---|---|
| 모델 (model) | 입력을 받아 출력을 내는, 학습된 거대한 함수 |
| 파라미터 (parameter) | 모델 안의 숫자 손잡이들. 학습이 조정하는 대상 |
| 학습/훈련 (training) | 데이터를 보여주며 파라미터를 조정하는 과정 |
| 추론 (inference) | 학습된 모델에 입력을 넣어 출력을 받는 것 (API 호출이 이것) |
| 토큰 (token) | 모델이 글을 읽고 쓰는 최소 조각. 요금/한도의 단위 → [02-LLM-기초](02-LLM-기초.md) |
| tokenizer | 텍스트 ↔ 토큰(숫자 ID) 변환기 |
| 컨텍스트 윈도우 | 모델이 한 번에 볼 수 있는 최대 토큰 수 |
| 프롬프트 (prompt) | 모델에게 보내는 입력 텍스트 전체 |
| temperature | 생성의 무작위성 손잡이 (낮음=일관, 높음=다양) |
| 환각 (hallucination) | 그럴듯한 거짓을 지어내는 현상 |
| 파인튜닝 (fine-tuning) | 학습된 모델을 내 데이터로 추가 학습 |

## RAG / 검색 (gongo-rag 쪽)

| 용어 | 한 줄 정의 |
|---|---|
| RAG | 검색한 근거를 프롬프트에 넣어 답하게 하는 구조 → [03-RAG-기초](03-RAG-기초.md) |
| chunk / chunking | 문서를 검색 단위 조각으로 자르기 / 그 조각 |
| 색인 (indexing) | 빠른 검색을 위해 미리 계산해두는 것 (BM25 통계, 임베딩 벡터) |
| BM25 | 단어 빈도+희귀성 기반 키워드 검색 알고리즘 → [BM25-완전정복](../04-concepts/BM25-완전정복.md) |
| TF (term frequency) | 단어가 그 문서에 몇 번 나오나 |
| IDF | 그 단어가 얼마나 희귀한가 (흔한 단어 벌점) |
| 임베딩 (embedding) | 텍스트를 의미를 담은 숫자 벡터로 바꾼 것 → [임베딩-완전정복](../04-concepts/임베딩-완전정복.md) |
| 코사인 유사도 | 두 벡터의 방향이 비슷한 정도 (-1~1) → [최소한의-수학](04-최소한의-수학.md) |
| top-k | 검색 결과 상위 k개 |
| hybrid search | BM25 점수 + 임베딩 점수 결합 검색 |
| reranking | 1차 검색 후보를 더 정밀한 모델로 재정렬 |
| 형태소 분석 | 한국어를 의미 단위로 쪼개기 ("지원금액은"→지원/금액/은) |
| 벡터 DB | 대량의 벡터를 빠르게 검색하는 전용 저장소 (소규모엔 불필요) |
| 골든셋 (golden set) | 사람이 만든 정답지 (질문+정답 근거). 평가의 기준 |
| hit rate@k | 골든셋 질문 중 정답이 top-k 안에 든 비율 |
| grounding / 근거성 | 답변이 실제 문서에 기반하는 성질 |
| precision (정밀도) | 내가 가져온 것 중 진짜의 비율 → [평가지표-완전정복](../04-concepts/평가지표-완전정복.md) |
| recall (재현율) | 진짜들 중 내가 가져온 것의 비율. hit@k가 이 계열 |
| F1 | precision과 recall의 조화평균 — 둘 다 좋아야 높음 |
| MRR | 정답의 순위까지 보는 지표: 1/(정답 순위)의 평균 |
| ANN | 근사 최근접 이웃 검색. 벡터가 수백만 개일 때 전수 비교 대신 쓰는 인덱스 (HNSW 등) — 벡터 DB의 핵심 기술 |

## 사전훈련 (tiny-pretraining 쪽)

| 용어 | 한 줄 정의 |
|---|---|
| pretraining | 대량 텍스트로 다음 토큰 예측을 학습시키는 첫 단계 → [사전훈련-원리](../04-concepts/사전훈련-원리.md) |
| next-token prediction | "지금까지를 보고 다음 토큰 맞히기" — LLM 학습의 본질 |
| loss | 모델이 얼마나 틀렸는지의 숫자. 낮을수록 좋음 (= -ln(정답 확률)) |
| cross-entropy | 분류 문제에서 쓰는 loss 공식의 이름 |
| optimizer | loss가 줄어드는 방향으로 파라미터를 갱신하는 알고리즘 (SGD, AdamW) |
| learning rate | 파라미터를 한 번에 얼마나 움직일지 (걸음 크기) |
| gradient (기울기) | 각 파라미터가 loss에 미치는 영향의 방향. `backward()`가 계산 |
| epoch / step | 데이터 전체 1바퀴 / 배치 1번 갱신 |
| batch | 한 번에 같이 처리하는 샘플 묶음 |
| embedding layer | 토큰 ID → 벡터 변환 표. 모델의 첫 층 (학습됨) |
| logits | softmax 전의 날 점수 |
| softmax | 점수를 합=1인 확률로 변환 |
| sampling | 확률분포에서 다음 토큰을 뽑는 행위 |
| overfitting | 훈련 데이터만 외워서 새 데이터(val)에 약해지는 것 |
| train/validation split | 공부용 데이터와 모의고사용 데이터 분리 |
| attention | 각 토큰이 앞 토큰들 중 어디를 얼마나 참고할지 계산 → [어텐션-개념](../04-concepts/어텐션-개념.md) |
| Transformer | attention을 쌓아 만든 구조. GPT/Claude의 뼈대 |
| GPU | 행렬 곱을 병렬로 하는 하드웨어. tiny엔 불필요 |
| 뉴런 / 층 / MLP | 가중합+활성화의 계산 단위 / 뉴런의 병렬 묶음 / 층을 쌓은 것 → [08-신경망-기초](08-신경망-기초.md) |
| 활성화 함수 (ReLU) | 층 사이에 비선형을 넣는 함수. 없으면 층을 쌓는 의미가 없음 |
| 역전파 (backprop) | 오차의 책임을 출력→입력으로 배분해 기울기를 구하는 알고리즘. `loss.backward()`의 정체 |
| 기울기 소실 | 깊은 망에서 학습 신호가 0으로 사라지는 문제. 잔차 연결이 해결 |
| dropout | 훈련 중 뉴런을 무작위로 꺼서 암기를 막는 기법 |
| weight decay | 큰 가중치에 벌점을 줘 과적합을 막는 기법. AdamW의 W |
| base vs instruct 모델 | 이어쓰기만 하는 사전훈련 결과물 vs 지시를 따르도록 SFT까지 한 모델 → [LLM학습-3단계](../04-concepts/LLM학습-3단계.md) |
| SFT (지시 튜닝) | (지시, 모범답변) 쌍으로 하는 추가 학습. 학습 방식은 여전히 next-token |
| RLHF / DPO | 사람의 선호(A vs B)를 모델에 반영하는 정렬 단계 |
| LoRA / PEFT | 원본 가중치를 얼리고 작은 어댑터만 학습하는 저비용 파인튜닝 / 그런 기법들의 총칭 |
| quantization (양자화) | 파라미터를 저비트로 압축해 실행 메모리를 줄이는 기법 |
| positional encoding | 순서를 모르는 attention에 위치 정보를 주입하는 방법 → [어텐션-개념](../04-concepts/어텐션-개념.md) 7절 |

## 취업 / JD에서 마주칠 단어

| 용어 | 한 줄 정의 |
|---|---|
| Applied AI Engineer | 기존 모델을 서비스 문제에 적용·평가·개선하는 엔지니어 (여러분의 목표) |
| 프롬프트 엔지니어링 | 프롬프트 설계로 출력 품질을 제어하는 기술 |
| LLMOps / MLOps | 모델 서비스의 배포·모니터링·운영 체계 |
| 서빙 (serving) | 모델을 API 형태로 운영하는 것 |
| LangChain / LlamaIndex | RAG 파이프라인 조립 라이브러리. *직접 구현해본 사람은 "왜 안 썼는지"를 말할 수 있어 오히려 강점* |
| 평가 (evaluation) | 출력 품질을 수치로 재는 것. JD 단골 키워드 — 여러분의 hit@k가 증거 |
| A/B 테스트 | 두 버전을 실사용자에게 나눠 비교 |
| RAG 파이프라인 | 수집→추출→청킹→색인→검색→생성→평가 전체 흐름 |
| fine-tuning vs RAG | 면접 단골 비교 → [02-LLM-기초](02-LLM-기초.md) 6번 |
| AI 에이전트 | LLM이 도구 호출을 반복하며 목표를 달성하는 루프 → [기술면접-확장질문](../05-career/기술면접-확장질문.md) E섹션 |
| function calling / tool use | 모델이 답 대신 "이 함수를 이 인자로 실행해달라"는 구조화된 요청을 출력하는 기능 |
| streaming | 답변을 토큰 단위로 흘려보내 체감 지연을 줄이는 전송 방식 |
| KV cache | 생성 시 이전 토큰들의 K·V를 저장해 재계산을 피하는 서빙 최적화 |
| FastAPI | 파이썬 API 서버 프레임워크. 데모(Streamlit)를 실서비스로 만들 때 쓰는 것 |
| Docker | 실행 환경을 통째로 포장해 어디서나 동일하게 실행하는 도구 |
