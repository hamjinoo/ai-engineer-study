# 02. LLM 기초 — 갖다 쓰는 사람이 알아야 할 최소한

> 읽는 시점: Week 1~2. gongo-rag에서 LLM API를 호출하기 전에.

## 1. 토큰 (token)

LLM은 글을 글자나 단어가 아니라 **토큰**이라는 조각 단위로 읽고 씁니다.

```
"지원금액은 최대 5천만원"
→ ["지원", "금액", "은", " 최대", " 5", "천만", "원"]   (예시 — 모델마다 다름)
```

- 영어는 대략 1토큰 ≈ 0.75단어, **한국어는 같은 내용도 토큰이 더 많이** 나옵니다.
- API 요금과 입력 한도가 모두 **토큰 수 기준**입니다.
- tiny pretraining에서는 가장 단순한 "1글자 = 1토큰" 방식(char-level)으로 직접 만들어봅니다.

## 2. 컨텍스트 윈도우 (context window)

모델이 **한 번에 볼 수 있는 토큰의 최대 개수**입니다. (예: 128K, 200K 토큰)

- 이 창 밖의 내용은 모델에게 **존재하지 않습니다**. "아까 말했잖아"가 안 통하는 이유.
- **RAG가 존재하는 이유 그 자체**: 공고문 100개를 통째로 넣을 수 없으니, 질문과 관련된 조각만 골라(검색) 창 안에 넣어주는 겁니다.

## 3. temperature — 창의성 손잡이

LLM은 다음 토큰을 "확률"로 예측한다고 했죠. temperature는 그 확률분포를 얼마나 평평하게 만들지 조절합니다.

| temperature | 효과 | 언제 |
|---|---|---|
| 0 ~ 0.3 | 거의 항상 1등 후보 선택 → 일관되고 보수적 | **RAG 답변 (우리 프로젝트!)**, 요약, 추출 |
| 0.7 ~ 1.0 | 다양한 후보 선택 → 창의적, 매번 다름 | 브레인스토밍, 창작 |

> gongo-rag에서는 사실만 답해야 하므로 **낮은 temperature**를 씁니다. tiny pretraining의 `generate()` 함수에서 이 손잡이를 직접 구현하면 원리가 완전히 이해됩니다.

## 4. API 호출의 기본 모양

LLM API는 결국 "메시지 목록을 보내면 답 텍스트가 온다"입니다.

```python
# 개념 모형 (실제 코드는 02-gongo-rag/src/rag_answer.py 에 완성돼 있음)
response = llm.chat(
    messages=[
        {"role": "system", "content": "너는 공고문 안내 도우미다. 근거 없는 말 금지."},
        {"role": "user",   "content": "신청 자격이 뭐야?"},
    ],
    temperature=0.2,
    max_tokens=1000,     # 답변 길이 상한 (토큰)
)
```

- `system`: 모델의 역할/규칙 지정. RAG에서는 "근거에 없으면 정보 없음이라고 답해"를 여기에 넣습니다.
- `user`: 사용자 입력. RAG에서는 **검색된 문서 조각 + 질문**을 합쳐서 넣습니다.
- 이 입력 텍스트 전체를 **프롬프트(prompt)** 라고 부릅니다.

## 5. 환각 (hallucination)

모델이 **그럴듯하지만 사실이 아닌 내용을 지어내는 것**. LLM은 "사실"이 아니라 "그럴듯한 다음 토큰"을 뽑는 기계라서 생기는 본질적 현상입니다.

RAG 프로젝트에서 환각을 줄이는 3중 장치 (전부 직접 만듭니다):
1. **검색**: 근거 문서를 프롬프트에 넣어준다
2. **프롬프트 규칙**: "근거에 없으면 '정보 없음'이라고 답하라"
3. **인용 검증**: 답변이 실제로 근거 chunk에서 나왔는지 코드로 확인

> 🎯 면접 단골: "환각은 검색 실패인가 생성 실패인가?" → 답은 "둘 다 가능하며, 분리해서 진단해야 한다"입니다. 정답 chunk가 검색에 없었으면 검색 실패, 있었는데 딴소리하면 생성 실패. 이 분리가 여러분 포트폴리오의 핵심 스토리입니다.

## 6. 파인튜닝 vs RAG (면접 단골)

내 데이터(공고문)를 모델에게 알려주는 두 가지 방법:

| | 파인튜닝 (fine-tuning) | RAG |
|---|---|---|
| 방법 | 모델의 파라미터를 내 데이터로 추가 학습 | 모델은 그대로, 검색한 근거를 프롬프트에 첨부 |
| 갱신 | 데이터 바뀌면 재학습 필요 (느림, 비쌈) | 문서만 갈아끼우면 됨 (즉시) |
| 출처 표시 | 어렵다 | 쉽다 (어느 chunk에서 왔는지 앎) |
| 적합한 경우 | 말투·형식 학습 | **사실 기반 Q&A ← 공고문 챗봇은 이쪽** |
