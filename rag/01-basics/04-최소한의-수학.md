## 1. 벡터 = 그냥 숫자 목록

```python
a = [3, 4]                  # 숫자 2개짜리 벡터 (평면 위의 화살표 하나)
b = [0.1, -0.5, 0.8, ...]   # 숫자 768개짜리 벡터 (임베딩이 이렇게 생김)
```

**게임 캐릭터로 생각하세요.** 캐릭터 능력치가 `[힘 3, 민첩 4]`면 이건 숫자 2개짜리 벡터입니다. 능력치가 768개인 캐릭터도 만들 수 있죠 — 상상은 안 되지만 **계산하는 방법은 완전히 똑같습니다.**

임베딩 모델은 문장을 숫자 768개짜리 목록으로 바꿉니다. 768차원은 그림으로 못 그리지만, **모든 계산은 2차원과 똑같습니다.** 2차원으로 이해하면 끝.

> ⚠️ 여기서 나중에 큰 사고가 납니다. 벡터를 "숫자 2개짜리"라고 생각하고 `a[0]`, `a[1]`만 쓰는 코드를 짜면, 진짜 768차원 벡터에서 앞의 2개만 보고 나머지 766개를 무시합니다. **에러도 안 나고 조용히 틀려요.** 항상 "숫자가 몇 개든 전부 훑는" 코드를 쓰세요.

## 2. 내적 (dot product) — 짝꿍끼리 곱해서 전부 더하기

이름만 무섭지, 하는 일은 **곱셈과 덧셈뿐**입니다.

```
a = (1, 2, 3),  b = (4, 5, 6)

  첫째끼리:  1 × 4 = 4
  둘째끼리:  2 × 5 = 10
  셋째끼리:  3 × 6 = 18
                     ─────
  전부 더하면        32     ← 이게 내적 (a · b = 32)
```

**의미**: 두 벡터가 **같은 쪽을 보는 정도**. 같은 방향이면 커지고, 직각(무관)이면 0, 반대 방향이면 음수가 됩니다.

## 3. 코사인 유사도 — 이번 주의 주인공

내적에는 억울한 문제가 하나 있습니다. **벡터가 "길기만" 해도 값이 커집니다.**

> 비유: 같은 방향으로 걷는 두 사람이 있는데, 한 명이 그냥 더 멀리 걸었다는 이유로 "너희 둘은 더 비슷하다"고 하면 이상하죠. 우리가 알고 싶은 건 **거리가 아니라 방향**입니다.

그래서 **각자의 길이로 나눠서** 순수하게 방향만 남깁니다. 그게 코사인 유사도:

```
cos(a, b) = (a · b) / (|a| × |b|)
             ↑          ↑
          내적      각 벡터의 길이

|a| = 벡터의 길이 = √(각 숫자를 제곱해서 전부 더한 값)
```

**"길이"는 왜 제곱하고 √를 씌우나?** 직각삼각형의 빗변 구하기(피타고라스)와 똑같습니다. 가로 3, 세로 4면 빗변은 5죠 → `√(3² + 4²) = √25 = 5`.

**손계산 ①** — 방향이 같으면 길이가 달라도 1:
```
a = (3, 4)   → |a| = √(9+16) = √25 = 5
b = (6, 8)   → |b| = √(36+64) = √100 = 10      (b는 a를 2배 늘린 것뿐!)
a·b = 3×6 + 4×8 = 18 + 32 = 50
cos = 50 / (5×10) = 1.0    ← 완전히 같은 방향! 길이 차이는 나눗셈에서 사라짐
```

**손계산 ②** — 직각이면 0:
```
a = (3, 4), c = (4, -3)
a·c = 3×4 + 4×(-3) = 12 - 12 = 0  →  cos = 0    ← 서로 아무 상관 없는 방향
```

| cos 값 | 해석 (임베딩 세계에서) |
|---|---|
| 1.0 근처 | 거의 같은 의미 ("지원금" ↔ "보조금") |
| 0.6~0.8 | 관련은 있음 |
| 0 근처 | 무관 ("지원금" ↔ "김치찌개") |
| 음수 | (문장 임베딩에선 드묾) 반대 성향 |

> 임베딩 검색 = "질문 벡터와 코사인 유사도가 가장 높은 chunk 벡터 k개 찾기". **이게 전부입니다.** `src/embeddings.py`에서 위 공식을 그대로 코드로 옮기면 됩니다.

## 4. 로그 (log) — "놀라움"을 재는 자

여기서 log는 자연로그 ln입니다. **성질 딱 두 개**만 알면 됩니다:

```
ln(1) = 0             ← 확률 100%로 맞힌 일이 일어남 → 하나도 안 놀람
ln(아주 작은 수) = 큰 음수 → 앞에 마이너스를 붙이면 큰 양수 → 엄청 놀람
```

**loss = -ln(모델이 정답에 준 확률)**, 즉 **"모델이 얼마나 놀랐나"** 입니다.

> 일기예보로 생각하세요. 예보관이 "비 올 확률 90%"라 했는데 비가 왔다 → 별로 안 놀람(loss 낮음, 좋은 예보관). "비 올 확률 1%"라 했는데 비가 쏟아졌다 → 완전 놀람(loss 높음, 나쁜 예보관).
> **학습 = 덜 놀라는 예보관이 되어가는 과정**입니다.

**-ln(확률) 감각표** (이게 곧 loss입니다):

| 모델이 정답에 준 확률 | -ln(확률) = loss | 해석 |
|---|---|---|
| 1.0 (100%) | 0.00 | 완벽 (전혀 안 놀람) |
| 0.9 | 0.11 | 훌륭 |
| 0.5 | 0.69 | 반반 (동전 던지기) |
| 0.25 | 1.39 | 4지선다 찍기 수준 |
| 0.01 | 4.61 | 거의 몰랐음 (깜짝 놀람) |

> **실전 팁 (외울 가치 있음)**: 학습 시작 전 모델은 아무것도 모르니까 모든 글자에 확률을 똑같이 나눠줍니다. 글자가 65종이면 각각 1/65 → loss = -ln(1/65) = **ln(65) ≈ 4.17**.
> 그래서 **초기 loss ≈ ln(vocab 크기)**. tiny pretraining에서 시작 loss가 4.17 근처면 "구현이 정상"이라는 신호입니다. **이론값과 내 코드가 만나는 첫 순간이라 짜릿합니다.**

## 5. softmax — 점수를 확률로 바꾸기

모델이 뱉는 건 처음엔 그냥 **점수**(logit)입니다. "다음 글자로 a는 2.0점, b는 1.0점, c는 0.1점". 이걸 **합이 1인 확률**로 바꿔야 제비뽑기를 할 수 있죠. 그 변환기가 **softmax**:

```
softmax: 각 점수에 exp()를 씌우고 → 전체 합으로 나눈다
```

**손계산**: 점수 (2.0, 1.0, 0.1) →
```
exp(2.0)=7.39,  exp(1.0)=2.72,  exp(0.1)=1.11    →  합 = 11.22

확률 = (7.39/11.22, 2.72/11.22, 1.11/11.22)
     = (0.66,       0.24,       0.10)     ← 전부 더하면 1! (=100%)
```

- **왜 그냥 나누지 않고 exp를 씌우나?** exp는 큰 점수를 **더 크게** 벌립니다 → 1등이 확률을 넉넉히 가져갑니다. (그리고 음수 점수도 양수로 바꿔줘서 확률로 쓸 수 있게 됩니다)
- **temperature(온도)**: softmax 하기 전에 점수를 T로 나눕니다.
  - T가 작으면(0.1) → 점수 차이가 벌어짐 → **1등만 뽑힘** (안전하지만 지루함)
  - T가 크면(3.0) → 점수 차이가 뭉개짐 → **아무나 뽑힘** (창의적이지만 헛소리 위험)
  - `03_bigram.py`의 `generate()`에서 직접 구현합니다.

## 6. 경사하강법 — 안개 낀 산에서 내려오기 (개념만)

학습 = "loss가 낮아지는 방향으로 파라미터를 조금씩 옮기기"

> **비유**: 안개가 자욱한 산에 서 있고, 아래로 내려가고 싶습니다. 산 전체 지도는 없어요. 할 수 있는 건 **발끝으로 주변을 더듬어 "어느 쪽이 내리막인지" 알아내고, 그쪽으로 한 걸음** 옮기는 것. 이걸 수천 번 반복하면 골짜기에 도착합니다.

```
새 파라미터 = 현재 파라미터 - learning_rate × 기울기
                                    ↑            ↑
                              한 걸음 크기   내리막 방향
```

- **기울기(gradient)** = "어느 쪽이 내리막인가". PyTorch가 `loss.backward()` 한 줄로 자동 계산해줍니다 (**미분 직접 안 합니다!**)
- **learning rate** = 한 걸음의 크기.
  - 너무 크면 → 골짜기를 훌쩍 건너뛰어 반대편 산으로 (loss가 튀거나 NaN)
  - 너무 작으면 → 하세월 (5000걸음 걸어도 제자리)
  - → 6주차 tiny 실험 주제가 바로 이 걸음 크기 찾기입니다.
