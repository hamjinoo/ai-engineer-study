# 면접 관문질문 공략 — 16문항 답변 설계도

> 계획서의 4/8/12주차 관문 질문 전부. **모범답안은 일부러 안 씁니다** — 남의 답을 외우면 꼬리질문 한 방에 무너집니다.
> 대신 각 질문마다 ① 좋은 답에 반드시 들어갈 요소 ② 내 프로젝트에서 가져올 증거 ③ 예상 꼬리질문을 줍니다.
> 사용법: 해당 주차가 끝날 때마다 **소리 내어** 답해보고, 12주차에 답변 스크립트를 직접 작성.

공통 답변 공식: **정의 한 줄 → 내 프로젝트에서의 경험/숫자 → 트레이드오프나 한계 → (여유가 되면) 다음 단계**
"교과서 정의만" 말하면 하수, "제 프로젝트에서는..."이 붙으면 중수, "단, ~한 경우엔 반대입니다"까지 가면 고수.

## RAG 8문항

### 1. chunk size는 왜 그렇게 정했나?
- **필수 요소**: 실험한 후보값들(300/500/1000) / 판단 지표(hit@3) / 양방향 트레이드오프(작으면 문맥 단절, 크면 노이즈 혼입+정답이 top-k 밖으로) / 내 데이터 특성(표 많은 공고문)
- **내 증거**: 실험③ 표
- **꼬리질문 대비**: "overlap은 왜 뒀나?" (경계에서 정답 문장 반토막 방지) / "문서 종류가 바뀌면?" (다시 실험 — 정답값이 아니라 실험 절차가 내 자산)

### 2. BM25와 embedding 검색은 뭐가 다른가?
- **필수 요소**: 원리 차이(어휘 일치 통계 vs 의미 벡터 유사도) / 각자의 승리 케이스(고유명사·금액 vs 패러프레이즈) / **내 골든셋에서의 유형별 승패 숫자**
- **내 증거**: 실험① + 유형별 분석표
- **꼬리질문**: "그래서 실무에선 뭘 쓰나?" (hybrid — 실험⑤ 숫자로 답변)

### 3. 한국어 검색에서 형태소 분석이 왜 필요한가?
- **필수 요소**: 조사 문제의 구체적 예("지원금액은" vs "지원 금액" — 매칭 0) / 형태소 분석이 하는 일(의미 단위 분해+조사 분리) / 적용 전후 hit@k 변화
- **내 증거**: 실험② / **꼬리질문**: "임베딩 검색에도 필요한가?" (임베딩은 의미 기반이라 덜 민감 — 이 대비를 말하면 강함)

### 4. top-k를 키우면 무조건 좋아지는가?
- **필수 요소**: "아니오" + 두 힘의 대립(검색 재현율↑ vs 프롬프트 노이즈↑로 생성 품질↓+비용↑) / 내 실험에서 꺾이는 지점
- **내 증거**: 실험④ (hit@k와 답변 품질을 따로 기록한 것이 결정타)

### 5. hallucination은 검색 실패인가 생성 실패인가?
- **필수 요소**: "둘 다 가능 — 그래서 **분리 진단**이 핵심" / 판정 절차(정답 chunk가 top-k에 있었나부터 확인) / 내 실패 10건의 분류 결과 숫자
- **내 증거**: Week 8 실패 분석표 — **이 질문이 여러분 포트폴리오의 존재 이유입니다**

### 6. 근거 인용 검증은 어떻게 했나?
- **필수 요소**: 프롬프트 규칙(근거 번호 인용 강제) + 코드 검증(`verify_citation` — 숫자/금액이 chunk에 실재하는지) + "정보 없음" 경로
- **내 증거**: `rag_answer.py` + no_answer 문항 처리율
- **꼬리질문**: "그 검증의 한계는?" (문자열 검사는 의미 왜곡을 못 잡음 → LLM-judge 등 다음 단계 언급)

### 7. RAG 평가 지표는 무엇을 봤나?
- **필수 요소**: 검색 지표(hit@3/@5)와 생성 평가를 **분리**한 이유 / 골든셋 설계(30~40문항, 유형 배분, 답 없는 질문 5개) / 왜 chunk 번호가 아니라 정답 문자열로 채점했나 (chunking 바꿔도 비교 가능)
- **내 증거**: `evaluate.py`의 설계 주석 + 골든셋

### 8. reranking은 언제 필요한가?
- **필수 요소**: 정의(1차 검색 후보를 정밀 모델로 재정렬) / 필요 신호(**hit@20은 높은데 hit@3이 낮다** = 후보엔 있는데 순위가 나쁨) / 비용(추가 모델 호출 지연)
- **내 증거**: 안 썼어도 됨 — "제 스케일에선 hit@3과 hit@5 차이가 작아 도입하지 않았고, 도입 판단 기준은 이렇게 세웠다"가 완벽한 답

## Pretraining 8문항

### 9. tokenization은 왜 필요한가?
- **필수 요소**: 신경망은 숫자만 계산 / 텍스트↔ID 양방향 규칙 / 문자 단위로 직접 구현한 경험(vocab 65, 왕복 검증)
- **꼬리질문**: "실제 LLM은 왜 문자 단위가 아닌가?" (시퀀스가 너무 길어짐 → BPE로 절충)

### 10. next-token prediction은 무엇인가?
- **필수 요소**: 정의 + **라벨이 공짜**라는 통찰(y는 x를 한 칸 민 것) + 왜 이 단순한 목표로 언어 능력이 생기나(다음 말을 맞히려면 문법·사실·문맥이 다 필요)
- **내 증거**: `02_dataset.py`의 x/y 출력을 직접 눈으로 검증한 경험

### 11. loss는 무엇을 의미하나?
- **필수 요소**: -ln(정답에 준 확률) = "놀라움" / 감각 수치(0.69=반반) / **초기 loss가 ln(vocab)인 이유와 그걸로 구현을 검증한 경험** ← 이 한 방이 실무자 인증
- **내 증거**: `03_bigram.py`의 4.17 체크

### 12. optimizer는 무엇을 바꾸는가?
- **필수 요소**: 파라미터(데이터도 loss식도 아님) / 4박자 리듬(forward→zero_grad→backward→step) / zero_grad를 빼먹으면 생기는 일
- **꼬리질문**: "SGD와 AdamW 차이?" (파라미터별 적응적 걸음 크기 — 개념 수준이면 충분)

### 13. embedding layer는 무엇을 학습하나?
- **필수 요소**: 토큰ID→벡터 룩업 표 / 무작위 시작 → 학습으로 "비슷한 문맥의 토큰이 비슷한 벡터"가 됨 / **gongo-rag의 임베딩 모델과의 연결** (임베딩-완전정복.md 7번의 킬러 멘트)

### 14. loss가 안 떨어지면 무엇을 의심하나?
- **필수 요소**: 점검 순서 — lr(큼: 튐/NaN, 작음: 정체) → 데이터(배치 decode해 눈으로) → zero_grad 누락 → 모델 용량 / **실제로 lr을 3종으로 바꿔본 곡선**
- **내 증거**: tiny README의 실험 표 + loss CSV

### 15. sampling temperature는 무엇을 조절하나?
- **필수 요소**: softmax 전 logits/T → 분포의 뾰족함 / T별 생성물을 직접 비교한 경험 / **RAG에 낮은 T를 쓴 이유와 연결** (두 프로젝트 관통!)

### 16. attention이 없으면 무엇이 어려운가?
- **필수 요소**: bigram 생성물이 헛소리인 직접 경험(직전 1토큰의 한계) / attention = 선택적 가중평균(Q·K·V) / **"attention은 곧 검색"** — 내 RAG 검색과의 구조 대응
- 상세: [어텐션-개념.md](../04-concepts/어텐션-개념.md) 6번
