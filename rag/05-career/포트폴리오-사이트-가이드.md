# 포트폴리오 사이트 가이드 — 뼈대는 지금, 내용은 주차별로

> 만드는 시점: **토요일 자유 탐구 슬롯에서만** (평일 침범 금지). 목표는 "완성"이 아니라 **구조 확정 + 빈칸 만들기**.
> 퍼블리셔 강점 활용 전략: 지금 Figma로 시안 → W9에 **직접 퍼블리싱** → 사이트 자체가 프론트 작업 샘플이 됨.

## 왜 "빈칸 버전"을 먼저 만드나

1. 포트폴리오의 주인공(실험 표 W6~7, 실패 분석 W8)은 아직 없다 — 지금 완성은 불가능하고, 흉내내면 빈 껍데기
2. 빈칸("[W6 기입 예정]")이 보이면 채우고 싶어진다 — 동기부여 장치
3. W9에 디자인 고민 없이 내용만 부으면 됨 — 9주차 부담 분산

## 구조 원칙 (포지셔닝 문서의 "채용 담당자가 읽는 순서" 그대로)

| 순서 | 섹션 | 주인공 |
|---|---|---|
| 1 | 히어로 | 포지셔닝 한 줄 (3초 안에 방향 전달) |
| 2 | gongo-rag | **실험 결과 표 + 실패 분석 표** ← 여기서 합격선 |
| 3 | tiny-pretraining | loss 곡선 + 학습 전/후 생성물 비교 |
| 4 | 전환 스토리 | 퍼블리셔 경험 → AI 언어 번역표, Widery/Sadam |
| 5 | 학습 기록 | 커밋 잔디 + 데일리 로그 발췌 (꾸준함 증거) |

핵심: **표와 숫자가 비주얼의 주인공.** 화려한 모션보다 "측정한 사람"이라는 인상.

## Figma 프롬프트 (전문)

```
채용 담당자를 위한 개발자 기술 포트폴리오 원페이지 웹사이트를 디자인해줘.

[대상과 목적]
- 주인공: 웹 퍼블리셔에서 Applied AI Engineer로 전환 중인 개발자
- 독자: AI 스타트업의 채용 담당자와 기술 면접관. 3초 스캔 → 30초 훑기 → 1분 정독의 흐름으로 읽는다
- 목적: "기능을 나열하는 지원자"가 아니라 "실험과 숫자로 말하는 지원자"라는 인상

[디자인 방향]
- 미니멀한 테크 리포트 스타일. 화려한 그래픽보다 타이포그래피와 표(table)가 주인공
- 국문 산세리프(Pretendard), 넉넉한 행간과 여백
- 라이트 배경 + 포인트 컬러는 블루 계열 1개만
- 데이터 표, 숫자, 코드 스니펫이 시각적으로 가장 돋보이게 (표는 카드형으로 승격)
- 데스크톱 1440px 기준 + 모바일 반응형 버전
- 아직 채워지지 않는 데이터 칸은 "[W6 기입 예정]" 스타일의 플레이스홀더 배지로 표시

[섹션 구성 — 순서 중요]

1. 히어로
- 이름, 한 줄 포지셔닝: "LLM/RAG를 서비스 문제에 적용하고, 검색 품질·근거성·환각·평가를
  함께 개선하는 Applied AI Engineer를 목표로 합니다"
- 서브 카피: "검색 실패와 생성 실패를 분리해 측정하고 설명합니다"
- 버튼 2개: GitHub / 이메일

2. 핵심 프로젝트: gongo-rag (한국어 공공문서 RAG)
- 문제 정의 한 줄: "정부 지원사업 공고문에 근거를 인용해 답하고, 근거가 없으면
  '정보 없음'이라 답하는 RAG 시스템"
- 파이프라인 다이어그램 자리: PDF수집 → 텍스트추출 → Chunking → BM25/임베딩 검색
  → LLM 생성 → 인용 검증 (가로 플로우)
- 하이라이트 카드 3개:
  (a) "BM25를 라이브러리 없이 직접 구현 — IDF·포화·길이보정을 손계산으로 검증"
  (b) "검색 품질 실험" + 표 자리: BM25 vs 임베딩 vs Hybrid × hit@3/hit@5 [W6-7 기입 예정]
  (c) "실패 분석" + 표 자리: 실패 10건을 검색실패/생성실패/데이터문제로 분류 [W8 기입 예정]
- 데모 스크린샷 자리 1개 [W11 기입 예정]

3. 서브 프로젝트: tiny-pretraining (LLM 밑바닥 이해)
- 카피: "문자 단위 언어모델을 PyTorch로 직접 구현 — tokenizer, next-token prediction,
  loss, optimizer, sampling의 흐름을 코드로 이해"
- loss 하강 곡선 그래프 자리 [W6 기입 예정] + 학습 전/후 생성 텍스트 비교 카드

4. 전환 스토리 (웹 퍼블리셔 → AI)
- 2단 비교: "퍼블리셔 경험" → "AI 직무에서의 의미" (예: 픽셀 검수 → 평가·QA 감각,
  디자인·개발 협업 → AI 기능을 서비스 흐름에 녹이는 감각)
- 이전 프로젝트 카드 2개: Widery, Sadam [설명 한 줄씩 기입 예정]

5. 학습 기록
- "12주 학습 로그" — GitHub 잔디 그래프 이미지 자리 + 데일리 로그 발췌 3줄
- 기술 스택 뱃지: Python, PyTorch, BM25, Sentence-Transformers, Git

6. 푸터: 이메일, GitHub, 블로그(기술글 1편 예정) 링크
```

**사용 팁**: 한 방에 끝내지 말고, 전체를 뽑은 뒤 "2번 섹션의 실험 표를 히어로급으로 키워줘"처럼 섹션별 후속 지시로 다듬는 게 결과가 좋습니다.
