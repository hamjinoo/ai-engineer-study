# 포지셔닝 · 이력서 · JD — 학습을 취업 언어로 번역하기

> 사용법: 매주 토요일 10% 루틴에서 조금씩 + 12주차에 집중.

## 1. 최종 포지셔닝 (계획서 원문 — 이력서 자기소개의 뼈대)

> 저는 모델을 새로 학습시키는 연구자라기보다, **LLM/RAG를 실제 서비스 문제에 적용하고 검색 품질, 근거성, 환각, 평가를 함께 개선하는 Applied AI Engineer**를 목표로 합니다.
> Widery와 Sadam에서는 AI 기능을 서비스 흐름 안에서 설계했고, gongo-rag에서는 한국어 공공문서 RAG의 검색·생성·평가 문제를 직접 구현과 실험으로 검증했습니다.
> 또한 tiny pretraining을 통해 tokenizer, next-token prediction, loss, optimizer, sampling의 흐름을 직접 코드로 구현하며 LLM의 기본 원리를 이해했습니다.

이 세 문장이 각각 **방향 / 증거1(적용) / 증거2(원리)**. 12주의 모든 산출물은 이 세 문장을 뒷받침하는 재료입니다.

## 2. 웹 퍼블리셔 경력은 약점이 아니라 차별점

숨기지 말고 이렇게 뒤집으세요:

| 퍼블리셔 경험 | AI 직무 언어로 번역 |
|---|---|
| 디자이너·기획·개발 사이에서 조율 | AI 기능을 **서비스 흐름 안에서** 설계하는 감각 (Widery/Sadam 스토리) |
| 사용자가 실제로 보는 화면을 책임 | 모델 출력이 **사용자에게 닿는 마지막 1미터**(UX·에러 상태·신뢰 표시)를 아는 엔지니어 |
| 브라우저 파편화 대응, 픽셀 검수 | 꼼꼼한 **평가·QA 감각** → 골든셋과 실패 분석으로 증명 |
| 접근성/시맨틱 마크업 | "정보 없음" 처리 같은 **책임 있는 출력 설계**와 같은 철학 |

## 3. 이력서 불릿 공식

**[한 것] + [어떻게/규모] + [숫자로 된 결과/발견]**. 나쁜 예→좋은 예:

- ❌ "RAG 챗봇을 개발했습니다"
- ⭕ "한국어 공고문 3종에 대한 RAG 시스템을 구축, 골든셋 35문항으로 BM25/임베딩/hybrid를 비교해 hit@3을 0.63→0.83으로 개선" *(숫자는 여러분의 실제 실험값으로)*
- ⭕ "실패 응답 10건을 검색/생성/데이터 문제로 분류, 원인의 40%가 PDF 표 추출 단계임을 규명하고 chunking 전략으로 완화"
- ⭕ "문자 단위 언어모델을 PyTorch로 밑바닥 구현(tokenizer→loss→sampling), 초기 loss=ln(vocab) 검증 등 학습 디버깅 체계 경험"

## 4. JD 키워드 → 내 증거 매핑표 (지원 전 5분 체크)

| JD에 이 말이 있으면 | 나의 증거 |

## 5. 채용 담당자가 README를 읽는 순서 (9주차에 이 순서로 재작성)

1. **제목+한 줄 소개** (3초): 무엇을, 왜 — "한국어 공공문서 RAG, 검색·생성 실패를 분리 측정"
2. **데모 스크린샷/GIF** (5초): 질문→답변→근거 인용이 보이게
3. **실험 결과 표** (30초): 여기서 "오, 측정을 했네"가 결정됨
4. **실패 분석 표** (1분): 여기서 "오, 생각을 하네"가 결정됨 — 합격선
5. 아키텍처/실행법: 여기까지 오면 이미 서류는 통과 분위기

→ 그러므로 README 상단에 3·4가 오도록. 설치법으로 시작하는 README는 아깝습니다.

## 6. 기술글 1편 (11주차) 개요 잡기

제목(계획서 추천): *한국어 공공문서 RAG를 만들며 검색 실패와 생성 실패를 분리해본 기록*

- 구성 제안: 문제(공고문 챗봇의 환각) → 측정 체계(골든셋/hit@k) → 실험 3개의 표 → 실패 부검 3건 (검색/생성/데이터 각 1건, 스크린샷) → 배운 것
- 규칙: 초안은 직접, GPT는 논리 검수만. 실험 표와 실패 사례가 글의 몸통 — 없으면 쓸 수 없는 글이 좋은 글입니다.
