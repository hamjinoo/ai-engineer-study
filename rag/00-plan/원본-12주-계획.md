# 최종 공부 방향

## 1️⃣ 목표

이번 3~4개월의 목표는 단순히 "포트폴리오 하나 만들기"가 아니라,

> **LLM/RAG를 실제 서비스에 붙일 수 있고,
> 검색·생성·평가 실패를 직접 설명할 수 있는 사람 되기**

야. 그래서 최종 축은 딱 2개만 둔다.

| 축 | 역할 |
| --- | --- |
| **gongo-rag** | RAG를 위에서 내려다보는 공부. 문서 검색, chunking, BM25, embedding, 평가, 근거 인용 |
| **tiny pretraining** | LLM을 아래에서 올려다보는 공부. tokenizer, next-token prediction, loss, optimizer, sampling, attention |

그리고 취업 준비는 완전히 빼지 않는다.
다만 초반에는 지원서보다 **학습을 취업 언어로 바꾸는 감각**만 유지한다.

# GPT 사용 규칙

## 언제든 물어봐도 되는 것
개념 설명 / 수식 의미 / 코드 리뷰 / 에러 원인 해석 / 실험 결과 해석 / 면접 꼬리질문 / README 피드백 / 기술글 논리 검수

## 막힌 뒤에만 물어볼 것
디버깅은 **30분 룰**. 질문 형식:
> "내 코드에서 이런 에러가 났고, 내가 시도한 건 A와 B야. 어디를 의심해야 할까?"
시도한 게 없으면 아직 물어보지 않는다.

## 맡기면 안 되는 것 (1~6주차)
chunker 전체 구현 / TF-IDF 전체 구현 / BM25 전체 구현 / cosine similarity 전체 구현 / hit rate@k 전체 구현 / 실패 분석 결론 작성 / 기술글 초안 전체 작성

## 맡겨도 되는 것
PDF 추출 보일러플레이트 / 파일 IO / API 호출 코드 / Supabase 연결 / Streamlit UI 뼈대 / 설치 문제 해결 / README 문장 다듬기

# 12주 최종 계획

## 1~4주차: 작게 완주
목표: **gongo-rag v0.1** + **tiny pretraining 기초 흐름 완성**

### gongo-rag
공고문 3개 수집 / PDF 텍스트 추출 / chunking 2종 구현 / 질문 10~20개 작성 / BM25 직접 구현 / embedding 검색 비교 / 간단한 RAG 답변 생성 / 근거 인용 검증 / 답 없는 질문에서 "정보 없음" 처리

### tiny pretraining
텍스트 불러오기 / 문자 단위 tokenizer / encode·decode / train·validation split / next-token prediction 데이터셋 / bigram model / loss 계산 / sampling

### 4주차 관문
> RAG는 어떤 단계로 동작하고, 각 단계에서 뭐가 실패할 수 있는가?
> LLM 사전훈련은 왜 next-token prediction인가?

## 5~8주차: 비교와 평가
목표: **감이 아니라 실험으로 말할 수 있는 상태**

### gongo-rag
골든셋 30~40개 작성 (답 없는 질문 5개 포함) / hit rate@3, @5 구현 / BM25 vs embedding 비교 / 형태소 분석 전후 비교 / chunk size 3종 비교 / top-k 3종 비교 / hybrid search 실험 / 실패 케이스 10개 분류 (검색 실패·생성 실패·데이터 문제)

### tiny pretraining
embedding layer 이해 / loss 감소 관찰 / train loss vs validation loss / learning rate 바꿔보기 / overfitting 관찰 / attention 개념 진입

### 8주차 관문
> 왜 어떤 질문은 BM25가 잘 맞고, 어떤 질문은 embedding이 잘 맞았는가?
> chunk size와 top-k를 바꾸면 검색과 생성 품질이 어떻게 달라졌는가?
> loss가 안 떨어지면 무엇을 의심해야 하는가?

## 9~12주차: 설명 가능한 사람으로 전환
목표: **기능 추가가 아니라 정리와 방어력**

### gongo-rag
README 완성 / 아키텍처 다이어그램 / 실험 결과 표 / 실패 사례 표 / 의사결정 이유 정리 / 간단한 데모 UI / 기술글 1편

추천 기술글 제목:
> 한국어 공공문서 RAG를 만들며 검색 실패와 생성 실패를 분리해본 기록

### tiny pretraining
README 작성 / tokenizer → loss → optimizer → sampling 흐름 정리 / attention 기초 정리 / gongo-rag의 embedding·token·context window와 연결해 설명

### 취업 전환
이력서에 gongo-rag 반영 / Widery·Sadam·gongo-rag 연결 / 면접 답변 스크립트 / JD 분석 시작 / 지원 재개

### 12주차 관문 질문

**RAG 쪽**: chunk size는 왜 그렇게 정했나? / BM25와 embedding 검색은 뭐가 다른가? / 한국어 검색에서 형태소 분석이 왜 필요한가? / top-k를 키우면 무조건 좋아지는가? / hallucination은 검색 실패인가 생성 실패인가? / 근거 인용 검증은 어떻게 했나? / RAG 평가 지표는 무엇을 봤나? / reranking은 언제 필요한가?

**pretraining 쪽**: tokenization은 왜 필요한가? / next-token prediction은 무엇인가? / loss는 무엇을 의미하나? / optimizer는 무엇을 바꾸는가? / embedding layer는 무엇을 학습하나? / loss가 안 떨어지면 무엇을 의심하나? / sampling temperature는 무엇을 조절하나? / attention이 없으면 무엇이 어려운가?
